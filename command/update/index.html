This documentation is for v14 and up, the docs for v13 are archived.

update

Update dependencies in your monorepo to newer versions from the npm registry. Checks for available updates and modifies package.json files (and pnpm-workspace.yaml catalog entries when present) to use them. Unlike fix which synchronises versions across packages, update fetches the latest published versions. Use --target to control update strategy (latest, minor, patch), or define updateGroups for per-dependency control. Versions newer than minimumReleaseAge are excluded by default to reduce supply chain attack risk.

Examples

Options

* ! { } etc

When passing values to synopkg via the command line, remember to add quotes around values containing special characters so your shell does not interpret them.

--check

List outdated dependencies instead of updating them and exit with a status code of 1 if updates are found.

synopkg update --check

--config <file-path>

synopkg searches the monorepo root directory for a config file which follows its naming convention, but this can be overridden by providing a path to a specific configuration file instead.

The only requirement is that the file must have a file extension and that it is one of .cjs, .cts, .js, .json, .mjs, .mts, .ts, .yaml, or .yml.

synopkg update --config ./config/synopkg.json

--dependencies <dependency-name-pattern>

Include dependencies whose name matches the given glob pattern.

To exclude, put a ! at the start of your query.

# Exact match for "react"
synopkg update --dependencies 'react'
# Substring match for "react"
synopkg update --dependencies '**react**'
# All dependencies under the AWS SDK scope
synopkg update --dependencies '@aws-sdk/**'
# Exact match for "react" or "webpack" (2 approaches)
synopkg update --dependencies 'react' --dependencies 'webpack'
synopkg update --dependencies '{react,webpack}'
# Substring match for "react" or "webpack" (2 approaches)
synopkg update --dependencies '**react**' --dependencies '**webpack**'
synopkg update --dependencies '**{react,webpack}**'

--dependency-types <comma-separated-dependency-type-names>

Include dependencies of the given dependency types and/or custom types.

To exclude, put a ! at the start of your query.

# devDependencies only
synopkg update --dependency-types dev
# dependencies and devDependencies only
synopkg update --dependency-types dev,prod
# everything except peerDependencies
synopkg update --dependency-types '!peer'

--dry-run

Cause synopkg to behave identically as when applying fixes, but never writing to disk.

synopkg update --dry-run

--interactive

Pick which updates to apply through an interactive prompt instead of writing every available update. Cannot be combined with --check.

Keys:

  • ↑ ↓: navigate
  • space: toggle the highlighted row
  • a: toggle all rows
  • enter: confirm and write selected updates
  • esc: cancel without writing
synopkg update --interactive

--log-levels <comma-separated-log-level-names>

Control how detailed the log output should be

LevelWhat is written to this channel
infoThe standard output which forms synopkg's UI, including lint issues
warnPossible mistakes in your setup, or highlights of known gaps in synopkg
errorFatal exceptions or errors outside the normal running of synopkg
debugExtremely verbose detail on why synopkg assigns each status code
# Turn off logging completely
synopkg update --log-levels off
# Only show verbose debugging logs
synopkg update --log-levels debug
# Show everything
synopkg update --log-levels error,warn,info,debug

--no-ansi

Synopkg will print colours and clickable hyperlinks to the terminal using ANSI escape code unless this option is set.

synopkg update --no-ansi

--no-cache

Bypass the on-disk cache of npm registry responses. By default Synopkg stores responses in the system temp directory for 30 minutes to avoid repeat network calls; this flag skips both reading and writing the cache for the current run.

synopkg update --no-cache

--source <file-pattern>

Only run synopkg update on package.json files matching the provided pattern(s).

Synopkg will look in the following places for glob patterns matching package.json files, in this order of precedence, and stop looking when a match is found:

  1. If --source CLI options are provided, use those.
  2. If source is defined in configuration, use that.
  3. If using npm workspaces or Yarn workspaces, read workspaces from ./package.json.
  4. If using pnpm, read packages from ./pnpm-workspace.yaml.
  5. If using Lerna, read packages from ./lerna.json.
  6. Default to 'package.json' and 'packages/*/package.json'.

Adding sources without replacing discovery

By default, --source and source replace the discovered patterns. To keep workspace discovery and add extra patterns on top, set sourceMode to "extend" (or pass --source-mode extend). Discovered patterns come first; your patterns are appended last, so gitignore-style negations such as !apps/legacy can exclude discovered entries.

# only the root package
synopkg update --source 'package.json'
# only packages matching a glob
synopkg update --source 'packages/beta-*'
# multiple values can be provided
synopkg update --source 'package.json' --source 'packages/beta-*'

--source-mode <replace|extend>

Control how --source (and the rcfile source) combine with workspace discovery. replace (default) uses only the supplied patterns and skips discovery; extend appends them after discovered patterns from workspaces / pnpm-workspace.yaml / lerna.json. Overrides sourceMode from the rcfile.

# Replace discovered patterns with the supplied ones (default)
synopkg update --source-mode replace --source 'packages/*/package.json'
# Append the supplied pattern to discovered workspace packages
synopkg update --source-mode extend --source 'tools/scripts/package.json'

--specifier-types <comma-separated-specifier-type-names>

Include only instances whose version specifiers are of the given specifier types.

To exclude, put a ! at the start of your query.

# Exact versions only
synopkg update --show instances --specifier-types exact
# Missing or unsupported versions
synopkg update --show instances --specifier-types missing,unsupported
# Latest or workspace protocol only
synopkg update --show instances --specifier-types latest,workspace-protocol

--target <greediness>

Limit updates to only those within the given semver portion. For per-dependency control, see updateGroups. When both apply to the same instance, the stricter of the two wins.

# Accept any update in latest (x.x.x)
synopkg update --target latest
# Only update minor versions (1.x.x)
synopkg update --target minor
# Only update patch versions (1.2.x)
synopkg update --target patch

--help

Display a list of CLI options and other help information.

# Display a short summary of commands and options
synopkg update -h
# Display full help with examples
synopkg update --help
